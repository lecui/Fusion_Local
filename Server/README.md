# Fusion Private Cloud — сервер аккаунтов и файлов

Пакет для собственного Linux VPS с Docker Engine и Docker Compose v2. Не зависит от TrueNAS или провайдера. Скрипт установки Docker предназначен для Ubuntu/Debian; на других Linux сначала установите Docker по инструкции дистрибутива. Ориентир для небольшой установки — 2 CPU, 2 ГБ RAM и место под модели и версии. Windows shared hosting без Docker не подходит.

## Что реализовано

- Аккаунты создаёт администратор через консоль VPS; открытой регистрации нет.
- Одна активная сессия на аккаунт. Успешный новый вход немедленно отзывает старый токен. Неудачный вход не отключает существующую сессию.
- Пароли хранятся как Argon2id-хеши; сервер хранит хеш токена, не сам токен.
- Сессия действует 30 дней, отзывается при выходе, сбросе пароля и блокировке аккаунта.
- Личное файловое пространство аккаунта, условные записи по ETag, хранение версий, корзина и восстановление.
- Файловый транспорт WebDAV: OPTIONS, PROPFIND (Depth 0/1), GET, HEAD, PUT, MKCOL, MOVE и DELETE. Это ограниченный транспорт для нашего клиента, **не полный WebDAV-сервер**: LOCK/UNLOCK/COPY, Range и рекурсивные операции над непустыми папками не реализованы. Не предназначен для подключения как стандартный сетевой диск Windows.
- Сервер требует Bearer-токен сессии для файловых операций. Постоянный пароль аккаунта используется только в `/v1/login`; обращаться к WebDAV по Basic Auth нельзя.

В текущую portable-сборку Fusion добавлено подключение к аккаунту, сохранение токена через Windows DPAPI и проверка сессии каждые 15 секунд, пока открыт экран с кнопкой подключения. Сервер проверяет токен независимо от этого интервала, при каждом запросе. Без интернета локальная копия продолжает работать, но доступа к облаку нет.

В портативной версии Fusion кнопка обновления в верхней панели запускает явную двустороннюю синхронизацию моделей. Новые локальные модели отправляются на сервер, отсутствующие локально модели загружаются в папку «С сервера», а одновременные изменения обеих копий помечаются как конфликт и не перезаписываются. Подключение аккаунта само по себе не отправляет модели: обмен начинается только после нажатия кнопки обновления.

## 1. Загрузить пакет на VPS

Распакуйте `fusion-cloud-server.zip` на сервере, например в `/opt/fusion-cloud-server`. Все дальнейшие команды выполняются в этой папке. Если архив распакован с дополнительным каталогом, перейдите в каталог, где находится `compose.yaml`.

Требуются свободные TCP-порты 80 и 443. Откройте их в firewall панели VPS. Скрипты не меняют firewall и не перезаписывают существующий веб-сервер.

Если Docker отсутствует, на Ubuntu/Debian:

```bash
sudo bash install-docker.sh
```

Скрипт подключает официальный репозиторий Docker. Если на машине уже установлены контейнерные пакеты, конфликтующие с Docker CE, разрешите конфликт согласно документации Docker; скрипт не удаляет их автоматически.

## 2. Запустить сервер

```bash
sudo bash install.sh
```

Установщик спросит:

1. IP или домен без `https://`.
2. Режим HTTPS: `1` — домен и публичный сертификат; `2` — IP и собственный сертификат.
3. Логин первого аккаунта (можно пропустить).
4. Пароль и повтор пароля. Пароль вводится скрыто, минимум 12 символов.

Для режима 1 DNS-запись A домена должна указывать на VPS. Запись AAAA должна быть корректной либо отсутствовать. Caddy получает и продлевает публичный сертификат автоматически.

Для режима 2 Caddy создаёт свой центр сертификации. Скрипт выгружает **только публичный** `client-ca.crt` в папку пакета. Скопируйте его на компьютер с Fusion по доверенному SSH/SCP-соединению. Приватные ключи остаются в Docker volume `caddy_data`.

Контейнер API не публикует порт 8000 в интернет. Внешние обращения проходят через HTTPS-прокси. Не публикуйте API отдельно и не запускайте несколько реплик: эта версия использует один процесс и локальную SQLite.

## 3. Подключиться из Fusion

После установки клиентского изменения перезапустите Fusion. На главном экране во вкладке «Последний» или «Удалённое» нажмите **«Подключиться к серверу»**.

- IP/адрес: `203.0.113.10` или `https://cloud.example.com` (адрес в примере замените своим).
- Логин: созданный на VPS аккаунт.
- Пароль: пароль аккаунта.
- Для режима 2 раскройте «Сертификат для подключения по IP» и укажите полный путь к скопированному `client-ca.crt`, например `C:\Users\Alexei\Documents\client-ca.crt`.

Для публичного сертификата поле сертификата оставьте пустым. HTTP и отключение проверки сертификата не поддерживаются. Файл сертификата должен оставаться на месте для последующих соединений. Он используется только этим клиентом: программа не добавляет его в системное хранилище доверия Windows.

Вход на втором компьютере завершает сессию первого. Локальные модели и несохранённая работа не удаляются. Пароль не сохраняется; токен защищён DPAPI текущего пользователя Windows в `%LOCALAPPDATA%\FusionPortableCloud\session.bin`. Это относится к нашему файловому аккаунту, а не к аккаунту Autodesk.

## Управление аккаунтами

```bash
sudo bash account.sh add-user alexei
sudo bash account.sh set-password alexei
sudo bash account.sh revoke alexei
sudo bash account.sh disable alexei
sudo bash account.sh enable alexei
sudo bash account.sh list-users
```

Не задавайте пароли аргументом командной строки. `set-password` и `disable` также завершают действующую сессию. Повторное включение аккаунта требует нового входа.

## Обслуживание и резервная копия

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 api proxy
sudo bash backup.sh
sudo bash stop.sh
sudo docker compose up -d
```

`backup.sh` на короткое время останавливает API, сохраняет каталог данных с согласованной SQLite, модели, версии, TLS-ключи и конфигурацию. После завершения API запускается снова. Архивы лежат в `backups`; переносите их на другой носитель. Они содержат чувствительные данные. Выход из аккаунта не делает ранее созданные резервные копии недействительными: после восстановления старой БД рекомендуется отозвать сессии аккаунтов.

Данные живут в Docker volumes и сохраняются при пересоздании контейнеров. **Не выполняйте `docker compose down -v`**, если хотите сохранить аккаунты и модели. При переносе на другой VPS сохраните также Caddy volume, иначе сертификат режима IP изменится и клиентам понадобится новый `client-ca.crt`.

Для обновления сначала создайте резервную копию, замените файлы пакета, затем выполните `docker compose up -d --build`. Файлы `.env`, `tls-mode.conf` и volumes оставьте прежними.

По умолчанию максимальный файл — 2 ГиБ, квота аккаунта — 20 ГиБ, включая историю версий и корзину. Параметры API меняются в `.env`; ограничение тела запроса прокси задаётся отдельно в `Caddyfile`. При увеличении максимального файла измените оба ограничения. Следите также за свободным местом диска VPS.

## API для файлового клиента

Все адреса ниже относительно HTTPS-адреса сервера. JSON имеет UTF-8-кодировку.

```text
POST /v1/login       {"username":"...","password":"...","device":"PC name"}
                     -> {"token":"...","username":"...","expires":epoch,...}
GET  /v1/session     Authorization: Bearer TOKEN
POST /v1/logout      Authorization: Bearer TOKEN
GET  /v1/files       -> {"items":[{"path":...,"kind":"file|folder","etag":...,"size":...}]}
GET  /v1/trash       -> {"items":[...]}
POST /v1/restore     {"path":"Models/part.f3d","etag":"\"...\""}
POST /v1/purge       {"path":"Models/part.f3d","etag":"\"...\"","confirm":true}
```

Каждый запрос, кроме `/healthz` и `/v1/login`, требует Bearer-токен. Ответ 401 означает, что сессия недействительна; клиент должен прекратить обмен и запросить вход. 429 — ограничение попыток входа на 15 минут.

```text
MKCOL    /dav/Models
PUT      /dav/Models/part.f3d   If-None-Match: *        (первое создание)
GET      /dav/Models/part.f3d
HEAD     /dav/Models/part.f3d
PROPFIND /dav/Models/          Depth: 1
PUT      /dav/Models/part.f3d   If-Match: "текущий-etag" (новая версия)
MOVE     /dav/Models/part.f3d   If-Match: "текущий-etag"
                              Destination: /dav/Models/new-name.f3d
DELETE   /dav/Models/part.f3d   If-Match: "текущий-etag" (в корзину)
```

ETag возвращается в HTTP-заголовке PUT/GET/HEAD и в JSON-списке. При повторной записи без ETag сервер вернёт 428, при устаревшем ETag — 412. Клиент должен запросить актуальный список и предложить пользователю разрешить конфликт. Имена URL кодируются в UTF-8 percent-encoding. Сервер не интерпретирует содержимое F3D/F3Z и не исправляет ссылки между моделями.

Окончательное удаление убирает серверные версии выбранного файла из рабочего хранилища. Оно не стирает копии в отдельно сохранённых административных backup-архивах. История версий хранится сервером; интерфейс выбора старой версии в Fusion пока не добавлен.

## Проверки этого выпуска

Серверные тесты: вход/отзыв/выход, сброс пароля, изоляция аккаунтов, WebDAV-чтение и запись, конфликты ETag, корзина и восстановление, лимиты размера/квоты, обход пути, ограничение попыток входа, отзыв во время загрузки.

Клиент проверен с настоящим локальным HTTPS-сервером: доверенный собственный сертификат, отказ недоверенному сертификату, шифрование сессии через DPAPI и отзыв при втором входе. Запуск Docker-контейнеров на вашем VPS необходимо выполнить после загрузки пакета: доступ к VPS в этой задаче не предоставлялся.
