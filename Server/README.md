# Fusion Private Cloud — сервер

Сервер аккаунтов и файлов для клиента Fusion Local. Разворачивается на Linux VPS с Docker Engine и Compose v2. Не зависит от TrueNAS или хостинг-провайдера. Это один экземпляр API с SQLite и HTTPS-прокси Caddy; сервер не запускает Fusion и не конвертирует STEP.

## Содержимое

| Путь | Назначение |
|---|---|
| `server/app.py` | Аккаунты, сессии, файлы, индекс синхронизации, версии и корзина |
| `server/manage.py` | Административные команды аккаунтов |
| `compose.yaml`, `Dockerfile` | Контейнеры API и Caddy, сети, постоянные volumes |
| `Caddyfile` | HTTPS, ограничение размера запроса, прокси; `default_sni` для соединения по IP |
| `install-docker.sh` | Установка Docker на Ubuntu/Debian из официального репозитория |
| `install.sh` | Настройка адреса/TLS, запуск и создание первого аккаунта |
| `account.sh` | Управление аккаунтами внутри контейнера |
| `backup.sh` | Согласованная резервная копия данных, конфигурации и TLS |
| `stop.sh` | Остановка без удаления данных |
| `fix-ip-https.sh` | Исправление старой конфигурации HTTPS по IP; новой установке не требуется |
| `requirements*.txt`, `tests/` | Зависимости приложения и тесты |

После установки создаются `.env`, `tls-mode.conf` и, для собственного CA, `client-ca.crt`. Они отсутствуют в репозитории намеренно.

## Возможности и ограничения

- Администратор создаёт аккаунты; открытой регистрации нет. Пароли — Argon2id-хеши, сервер хранит хеш токена.
- Одна активная сессия на аккаунт. Новый успешный вход отзывает старый токен; срок сессии по умолчанию 30 дней.
- Раздельное файловое пространство пользователей, ETag для защиты от перезаписи, история версий, корзина.
- WebDAV — ограниченный транспорт: OPTIONS, PROPFIND Depth 0/1, GET, HEAD, PUT, MKCOL, MOVE, DELETE. LOCK/UNLOCK/COPY, Range и рекурсивное удаление непустых папок не реализованы. Это не стандартный сетевой диск Windows.
- Файловые запросы используют Bearer-токен. Basic Auth по постоянному паролю не поддерживается.
- Используется один процесс API и локальная SQLite; не увеличивайте число реплик/workers.
- Сервер не интерпретирует F3D/F3Z и внешние ссылки сборок. Выбор старой версии в интерфейсе Fusion пока не реализован.

## 1. Подготовка VPS

Нужны Linux, SSH, права администратора, свободные TCP 80/443 и место для файлов, истории и резервных копий. Начальный ориентир для небольшой установки — 2 CPU и 2 ГБ RAM; потребность зависит от нагрузки.

Скопируйте содержимое `Server` в отдельный каталог, например `/opt/fusion-cloud-server`. Далее:

```bash
cd /opt/fusion-cloud-server
sudo bash install-docker.sh
docker compose version
```

Скрипт установки Docker поддерживает Ubuntu/Debian и не удаляет автоматически конфликтующие контейнерные пакеты. На другом Linux сначала установите Docker Engine и Compose v2 средствами дистрибутива.

Откройте 80 и 443 в firewall ОС и панели VPS, сохранив доступ по SSH. Установщик не меняет firewall и не освобождает занятые порты. API 8000 наружу не публикуется.

## 2. HTTPS и запуск

```bash
sudo bash install.sh
```

Введите IP/домен без `https://`, затем режим сертификата:

1. **Домен / публичный HTTPS**: DNS A указывает на VPS, AAAA корректна или отсутствует. Caddy получает и продлевает сертификат автоматически.
2. **IP / собственный CA**: Caddy создаёт свой центр сертификации. Установщик сохраняет публичный `client-ca.crt` рядом с `compose.yaml`. Передайте его на ПК по доверенному SSH/SCP. Приватные ключи остаются в volume `caddy_data`.

Затем можно создать аккаунт: логин и пароль, минимум 12 символов. Пароль вводится скрыто с подтверждением. Linux-пользователь `root` не является автоматически аккаунтом приложения.

Повторный запуск установщика сохраняет `.env` и `tls-mode.conf`. Для смены адреса/TLS сначала сделайте резервную копию и согласованно измените конфигурацию.

Проверка:

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 api proxy
curl --cacert client-ca.crt https://203.0.113.10/healthz
```

Замените пример IP своим. Для публичного доменного сертификата используйте `curl https://cloud.example.com/healthz` без `--cacert`.

## 3. Подключение клиента

Установите патч по [README клиента](../Client/README.md). Нажмите **часы справа вверху Fusion**, откройте подключение, введите адрес и аккаунт сервера. Для собственного CA укажите абсолютный путь к `client-ca.crt`; для публичного сертификата поле оставьте пустым. HTTP и отключение проверки сертификата не поддерживаются.

Подключение запускает фоновую синхронизацию. Сохранения моделей и зарегистрированные файловые операции ставятся в очередь; обновление левой панели запускает обмен вручную. В офлайне очередь хранится на ПК и выполняется после подключения. После потери связи клиент приостанавливает повторные проверки до ручного подключения.

Первый ПК узнаёт о входе со второго при проверке сессии (примерно каждые 10 секунд онлайн) либо файловом запросе, переходит офлайн и показывает уведомление. Данные входа сохраняются для повторного подключения и защищены Windows DPAPI. При переносе на другой ПК нужно войти заново.

Логические пути моделей: `FusionModels/files/<id>.f3d`; свойства: `FusionModels/meta/<id>.json`. Это не обычная папка с логином на VPS: физические данные хранятся по внутренним идентификаторам пользователей и хешам объектов. Не переименовывайте их вручную.

Для загрузки в новый проект создайте соответствующий корневой проект на принимающем ПК. Автоматическое зеркалирование пустых папок и всех изменений структуры существующих моделей не реализовано полностью. При независимом изменении обеих копий требуется разрешение конфликта пользователем; автоматического объединения геометрии нет.

## Аккаунты

```bash
sudo bash account.sh add-user alexei
sudo bash account.sh set-password alexei
sudo bash account.sh revoke alexei
sudo bash account.sh disable alexei
sudo bash account.sh enable alexei
sudo bash account.sh list-users
```

Не передавайте пароль параметром командной строки. Смена пароля и блокировка завершают сессию. `revoke` отключает сессию без удаления файлов; `enable` снимает блокировку, но требуется новый вход. Команды удаления аккаунта нет.

## Настройки и хранение

`.env` содержит `SITE_ADDRESS`, `MAX_FILE_BYTES=2147483648` и `ACCOUNT_QUOTA_BYTES=21474836480`. По умолчанию файл ограничен 2 ГиБ, аккаунт — 20 ГиБ с учётом версий и корзины. В `Caddyfile` отдельно задан предел тела запроса `2GB`: проверяйте оба ограничения и их единицы. Срок сессии `SESSION_SECONDS: 2592000` задаётся в `compose.yaml`. После изменения примените `sudo docker compose up -d`.

Volumes: `cloud_data` — база и файловые объекты; `caddy_data` — TLS-ключи/сертификаты; `caddy_config` — данные Caddy. Compose добавляет префикс `fusion-cloud` к именам volumes. **Не выполняйте `docker compose down -v`, если нужно сохранить данные.**

## Обслуживание и обновление

```bash
sudo bash backup.sh
sudo bash stop.sh
sudo docker compose up -d
```

`backup.sh` кратковременно останавливает API, копирует данные и TLS в `backups/<UTC-время>/`, создаёт `.tar.gz` и запускает API обратно. Каталог и архив содержат приватные данные; храните их вне публичного репозитория и дополнительно вне VPS.

Для обновления сделайте backup, замените программные файлы пакета, сохранив `.env`, `tls-mode.conf`, сертификат и volumes, затем:

```bash
sudo docker compose up -d --build --wait --wait-timeout 180
sudo docker compose ps
sudo docker compose logs --tail=100 api proxy
```

### Восстановление / перенос

1. Сохраните текущую установку отдельно. Распакуйте backup: должны быть `data`, `tls-data`, `.env`, `Caddyfile`, `tls-mode.conf`.
2. На новом VPS разместите ту же версию серверного пакета и три файла конфигурации из backup. При необходимости обновите DNS/адрес.
3. Выполните `sudo docker compose create --build`. Для существующего сервера сначала остановите контейнеры.
4. На **новые пустые volumes** скопируйте данные (замените путь):

```bash
sudo docker compose cp /path/to/backup/data/. api:/data/
sudo docker compose cp /path/to/backup/tls-data/. proxy:/data/
sudo docker compose run --rm --no-deps --user root --cap-add CHOWN --entrypoint sh api -c 'chown -R 10001:10001 /data'
sudo docker compose up -d --wait --wait-timeout 180
```

Не смешивайте разные копии в заполненном volume. Для существующего заполненного хранилища восстановите отдельную установку и переключитесь после проверки. Сохранение TLS CA позволяет оставить прежний `client-ca.crt`; при смене CA замените его на ПК. После восстановления старой БД отзовите сессии командой `account.sh revoke LOGIN` и войдите заново.

## Ошибки

| Симптом | Проверка |
|---|---|
| `invalid option name ... pipefail` | Windows CRLF в скрипте. Для старой копии: `sed -i 's/\r$//' *.sh`; затем запускайте через `bash`. В репозитории закреплён LF |
| Тайм-аут | Адрес, TCP 443, firewall, `docker compose ps`, журнал proxy; после исправления подключитесь заново |
| `TLSV1_ALERT_INTERNAL_ERROR` по IP | `default_sni` в Caddyfile; для старой установки: `sudo bash fix-ip-https.sh` |
| Недоверенный сертификат | CA именно этого сервера, полный путь к нему, корректное время Windows |
| 401 | Сессия отозвана/истекла, нужен новый вход |
| 412 | Конфликт версии ETag; обновите список и сохраните конфликтующие копии отдельно |
| 413 / 507 | Лимит файла / квота; проверьте также свободное место VPS |

## API и проверки

Операции приложения, кроме `/healthz` и `/v1/login`, требуют `Authorization: Bearer TOKEN`; служебный WebDAV OPTIONS допускается отдельно.

```text
POST /v1/login       {username, password, device}
GET  /v1/session
POST /v1/logout
GET  /v1/files
GET  /v1/sync-index
GET  /v1/trash
POST /v1/restore     {path, etag}
POST /v1/purge       {path, etag, confirm: true}
GET/HEAD/PUT/DELETE/MKCOL/MOVE/PROPFIND /dav/<path>
```

Первый PUT: `If-None-Match: *`; замена/удаление: `If-Match` с текущим ETag. Без нужного условия — 428, при конфликте — 412. DELETE отправляет запись в корзину. Purge удаляет серверные версии, но не административные backups. URL кодируется UTF-8 percent-encoding.

Для тестов в отдельном окружении:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-test.txt
pytest tests -q
```

При подготовке выпуска прошли 6 серверных тестов. Развёртывание Docker/TLS на VPS и восстановление backup в этой проверке не выполнялись; перед восстановлением единственной копии проверьте процедуру на отдельной установке.
